## Fixtures and assertion rules

Use `make_user(roles=(), with_profile=True, **fields)`, `make_profile(user, **fields)` from the proposed shared interface, explicit role creation, two unrelated users/targets, a `controlled_clock` and `temporary_media()` returning a Path and deterministic tiny synthetic image bytes. Propose shared `isolated_admin_settings(admin_mount=...)`, isolated static-root helper, and `snapshot_business_state()` interfaces; coordinator must settle location before implementation. Avoid importing another domain's test internals. Domain owners expose reusable assertions for seeded workflow fields; do not duplicate their approval/permission rule suites here.

Unless stated otherwise, each case snapshots unrelated users/profiles, HOME rows, role memberships and sentinel files; after action reload via ORM and compare all unmentioned fields/records unchanged. Public read cases check no business DB/file changes and unchanged authenticated identity. Assertions describe intended test pseudocode, not executed results. P cases use TestCase, pure cache callback uses SimpleTestCase, commit/storage failures and races use TransactionTestCase where transaction boundaries matter. Only injected DB/storage failure boundaries are mocked. Model saves do not call full_clean; form validation must be tested independently.
